# Pika Badminton

A two-player Pikachu badminton game that runs in the browser (personal fan project). Play two on one keyboard, or online with a friend.

## Run

```bash
python3 -m http.server 8777 --directory badminton
```

Open http://localhost:8777 in a browser. The controls are listed under the game screen.

## Layout

```
badminton/
  index.html            game page, controls, online panel
  game.js               the whole game (physics, moves, rendering, online play)
  rollback.js           rollback netcode: input exchange, prediction, rewind and replay, time sync, desync check
  detmath.js            sin/cos/atan2/hypot that give the same bits in every browser (online games must match)
  pikachu_grid.json     Pikachu sprite (generated by art/pikachu_pixel.py)
  art/pikachu_pixel.py  the Pikachu pixel art source; edit and rerun to change the sprite
  art/pikachu_pixel.png preview of the art
  vendor/pixelfx/       pixel effects library (MIT), only the parts the game uses
```

To change the sprite: edit `art/pikachu_pixel.py`, run `python3 art/pikachu_pixel.py` from the `badminton` folder, then reload the game.

## Tests

```bash
node tests/rollback.test.mjs
node tests/detmath.test.mjs
```

The first plays two rollback sessions against each other over a simulated network (latency, jitter, loss, Wi-Fi stalls, a hidden tab) and checks both end with exactly the same game. The second checks `detmath.js` gives the same bits in V8 (Chrome) and, on a Mac, JavaScriptCore (Safari).

Online, anything that changes the game state must give the same result in every browser: use `srand()` instead of `Math.random()`, and `detmath.js` instead of `Math.sin`, `Math.cos`, `Math.atan2` and `Math.hypot` (those differ between Chrome and Safari). New state goes in `saveState`/`loadState` too. If the two games ever drift apart anyway, a check once a second notices and the host's state is copied over.
