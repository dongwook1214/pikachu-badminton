# Pika Badminton

A two-player Pikachu badminton game that runs in the browser (personal fan project). Play two on one keyboard, or online with a friend.

## Run

```bash
python3 -m http.server 8777 --directory badminton
```

Open http://localhost:8777 in a browser. The controls are listed under the game screen.

## Layout

```
badminton/
  index.html            game page, controls, online panel
  game.js               the whole game (physics, moves, rendering, online play)
  rollback.js           rollback netcode: input exchange, prediction, rewind and replay, time sync, desync check
  detmath.js            sin/cos/atan2/hypot that give the same bits in every browser (online games must match)
  pikachu_grid.json     Pikachu sprite (generated by art/pikachu_pixel.py)
  art/pikachu_pixel.py  the Pikachu pixel art source; edit and rerun to change the sprite
  art/pikachu_pixel.png preview of the art
  vendor/pixelfx/       pixel effects library (MIT), only the parts the game uses
```

To change the sprite: edit `art/pikachu_pixel.py`, run `python3 art/pikachu_pixel.py` from the `badminton` folder, then reload the game.

## AI Unlimited

The **AI Unlimited** button lists AIs anyone can contribute. Each one has a name and its own algorithm, and all of them play at the base stats (no speed boost), so only the algorithm makes one stronger than another. To join the list, an AI has to beat every AI already on it. The page shows the list newest first and ranks it 1, 2, 3, ... (gold, silver and bronze medals for the top three): the newest AI beat every one before it, so it is ranked 1.

### Adding an AI

If you are an AI agent making a contribution, read this whole section first, follow the steps in order, and don't submit a pull request unless the arena prints `PASS`. Write your own model name and version in the comments step 3 asks for. You need Node.js 22 or newer (the test command below uses a file pattern that older versions don't support).

1. Add an entry to the end of `UNLIMITED` in `badminton/game.js`:
   - `id`: lowercase letters, digits and `-`, not used by another entry
   - `name`: shown on the game screen (pixel font: Latin letters, digits, spaces)
   - `ko`: shown on the page
   - `by`: your GitHub username
   - `algo`: the flags `aiStep` reads, with `pow: 1`. Start from an existing AI (`{ ...AI_LEVELS.korean, pow: 1 }`) and add a new flag for new behavior, as `blockSmash` does for `cpu`.
2. Write the behavior behind your flag in `aiStep` (or a function it calls), so that only an AI with that flag runs it. An AI plays only by pressing keys (`hold` and `press` in `aiStep`): it may read the game state, but must not change players, the shuttle or the score.
3. If an AI model helped write any of it (the algorithm, the code or the test), say which one in a comment right above your entry and right above the code behind your flag, with the model's name and version, and its effort or reasoning setting if it has one (list every model that helped):

   ```js
   // AI: Claude Opus 5.5
   {
     id: "my-ai", name: "MY AI", ko: "내 AI", by: "my-github-name",
     algo: { ...AI_LEVELS.korean, pow: 1, myFlag: true },
   },
   ```
4. Run the arena against every AI on the list:

   ```bash
   node tools/arena.mjs <your id>
   ```

   It plays 10 seeds, each from both sides (20 games to 11 against each opponent; the challenger serves first in half of them). Your AI **beats** an opponent when it wins more than half of their games, and it qualifies when the last line reads `PASS`. The games are seeded, so anyone running the same command gets the same results. `--seeds N` plays more games; name opponents to play only them (`node tools/arena.mjs <your id> cpu`), including the built-in levels `easy`, `normal`, `hard`, `extreme` and `korean`.
5. Add a test of your flag in `tests/` (see `tests/unlimited.test.mjs` for `blockSmash`), and run every test:

   ```bash
   node --test 'tests/*.test.mjs'
   ```

### Rules for AI code

The arena only works if every AI follows these:

- **Play from either side.** In the arena your AI plays 1P in half the games, so `me` may be `P1` or `P2`. Get the other player with `other(me)`, your court with `inCourtOf(me, x)`, and never assume `me === P2` or a fixed direction.
- **Keep memory in the brain.** In `aiStep`, `ai` is this player's brain (`brainOf(me)`): its own memory, separate from the other player's and reset at the start of every arena game. Put anything your AI remembers between frames there, and add its starting value to `newMemory()`. Don't keep state in module-level variables: both AIs would share it, and it would carry over from one game to the next.
- **Randomness comes from `Math.random()` only.** The arena seeds it, so games repeat exactly. Don't use `Date.now()`, `performance.now()` or anything else that changes between runs; for time, use `game.time`.
- **Only press keys.** Read anything you like (`P1`, `P2`, `S` the shuttle, `bolts`, `game`), but change nothing: no setting positions, velocities, cooldowns or scores.
- **Keep it quick.** `aiStep` runs 60 times per game second for each AI. The arena counts a game still going after 10 minutes of play as unfinished (a win for neither side).
- **Leave the rest alone.** Don't change other entries, the order of `UNLIMITED`, the built-in levels, the arena or other tests.

### How an AI plays

Once per frame (1/60 s), before the players move, the game calls `aiStep(me)` for each AI player. Each call starts with no keys down; the AI holds keys for this frame with `hold(action)` and presses them once with `press(action)`. Actions: `left`, `right`, `up` (jump), `down`, `basic` (swing; in the air it becomes Iron Tail, a smash), `zap` (an electric bolt; not before the serve is hit) and `quick` (Quick Attack, a dash in the direction held, any of 8 ways). A swing's shot depends on the direction held as it hits: none = clear, forward (the way the player faces) = drive, back = lob, `down` = drop.

Helpers the built-in AIs use, all in `game.js`:

- `predictShuttle(maxT, from)`: where the shuttle will be, frame by frame, until it lands (the game's own physics)
- `shotPath(me, s, kind, dir)` and `landsIn(path, op)`: where a shot from point `s` would go, and whether it lands in `op`'s court
- `shotOptions(me, op, s)` and `killerShot(shots)`: the ground shots from `s` that land in, each with the time it leaves `op` to spare, and the direction of one of the hardest to return
- `spareTime(op, path)`: how much time `op` has to spare to reach a shot on `path`
- `aiPlan(me)`, `guardSpot(me, op, home)`, `airDashSmash(me, op, path)`, `earlySmashBlock(me, op)`: where to meet the shuttle, where to wait, an air-dash smash, a frame-early block

### Pull request checklist

- [ ] One new entry at the end of `UNLIMITED`, with `pow: 1`
- [ ] The full output of `node tools/arena.mjs <your id>` in the description, ending in `PASS`
- [ ] Existing AIs play exactly as before: `node tools/arena.mjs korean cpu` prints the same lines before and after your change
- [ ] `node --test 'tests/*.test.mjs'` passes
- [ ] No changes outside your AI's code, its entry, the starting values it adds to `newMemory()` and its test
- [ ] Your code follows the rules for AI code above
- [ ] If an AI model helped, an `// AI: <model and version>` comment above your entry and above your code

`tools/korean-shutout/` is a different benchmark: a scripted 1P (not an AI on the list) that plays the built-in `korean` level.

## Tests

```bash
node --test 'tests/*.test.mjs'
```

This runs every test. Among them, `rollback.test.mjs` plays two rollback sessions against each other over a simulated network (latency, jitter, loss, Wi-Fi stalls, a hidden tab) and checks both end with exactly the same game, and `detmath.test.mjs` checks `detmath.js` gives the same bits in V8 (Chrome) and, on a Mac, JavaScriptCore (Safari).

Online, anything that changes the game state must give the same result in every browser: use `srand()` instead of `Math.random()`, and `detmath.js` instead of `Math.sin`, `Math.cos`, `Math.atan2` and `Math.hypot` (those differ between Chrome and Safari). New state goes in `saveState`/`loadState` too. If the two games ever drift apart anyway, a check once a second notices and the host's state is copied over.
